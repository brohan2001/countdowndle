## 2. How to run locally

```bash
pnpm install && pnpm dev                 # http://localhost:3000; solo games + daily need nothing else
open -a Docker && supabase start         # for accounts, duels, feedback, integration tests
```
- `.env.local` holds the LOCAL Supabase keys plus a `VERCEL_OIDC_TOKEN` that `vercel link` added.
- Gate before any commit: `pnpm exec next typegen && pnpm tsc --noEmit && pnpm lint && pnpm test:run`, plus `pnpm build` at milestone ends.
- Integration tests skip cleanly without the local stack.
- E2E: see `docs/E2E.md`. `scripts/e2e-duel.mjs` takes `BASE_URL` (default :3000) and `REPO_ROOT`, a folder whose `.env.local` points at the target Supabase. It covers inline guest join, a full match and a resign match.

## 6. Gotchas

- Next 16: middleware is `proxy.ts`; read `node_modules/next/dist/docs/` before using Next APIs. `PageProps`/`LayoutProps` are generated by `next typegen`.
- Vitest runs the body of `describe.skip`, so never construct clients from possibly-undefined env there.
- Supabase does NOT auto-grant table privileges; migrations GRANT explicitly. pgTAP runs as `postgres`, so only the integration tests catch a missing grant.
- `matches.state` is redacted mid-round and rehydrated from `round_submissions`; keep that invariant.
- Scripts: `node_modules/.bin/tsx`. macOS has no `timeout`.
- Browser QA: Playwright lives outside the repo (job tmp), using Chromium headless shell 1223. The chrome-devtools MCP is configured at user scope and loads in new sessions.
